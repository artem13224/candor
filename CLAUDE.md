## Commands

```bash
# Scaffold a new post from scripts/templates/post.html → blog/<slug>.html
npm run new-post -- "Post title" --tag "Process" [--date YYYY-MM-DD] [--lede "..."] [--description "..."] [--read 6] [--og-image URL] [--dry-run]

# Validate one post, or every post in blog/ (non-zero exit on problems)
node scripts/validate-post.js blog/post.html
npm run validate

# Regenerate blog/index.html cards + the blog <url> block of sitemap.xml from blog/*.html
npm run rebuild

# Publish: copy into blog/ → sync-shared → validate → rebuild index + sitemap → git add/commit/push
npm run publish -- path/to/post.html            # or: node scripts/publish.js path/to/post.html
node scripts/publish.js path/to/post.html --dry-run   # rehearse everything, write nothing
node scripts/publish.js path/to/post.html --no-git    # write files, skip git
node scripts/publish.js path/to/post.html --force     # publish despite validation problems

# Rebuild index + sitemap whenever blog/*.html changes (dev convenience)
npm run watch
```

All blog logic lives in `scripts/lib/blog.js` — `extractPost`, `validatePost`, `listPosts`, `rebuildIndex`, `rebuildSitemap`, `ALLOWED_TAGS`. The CLIs (`new-post.js`, `validate-post.js`, `rebuild.js`, `publish.js`, `blog-watcher.js`) are thin wrappers over it. `publish.js` reads metadata from `<head>` (title, description, `article:section`, JSON-LD dates), refuses to publish a post that fails validation, commits with message `blog: publish {slug}` and pushes. `scripts/sync-shared.js` injects the site-wide consent banner, footer links and a11y block; `publish.js` runs it on the post being published. The end-to-end flow for Claude is documented in `.claude/skills/blog-publish/SKILL.md`.

## Blog system

Pipeline: `new-post.js` scaffold → write the article → `validate-post.js` → `publish.js --dry-run` → `publish.js`. The step-by-step flow (and the rules below) is in `.claude/skills/blog-publish/SKILL.md`. The canonical post skeleton is `scripts/templates/post.html` (derived from `blog/b-lab-verification-process.html`); it lives outside `blog/` so the watcher never lists it.

### Allowed tags

`B Corp Basics` · `Process` · `Certifications` — exported as `ALLOWED_TAGS` in `scripts/lib/blog.js`. `<meta name="article:section">` and `<span class="article-tag">` must both use one of these and match each other. The filter buttons on `blog/index.html` are built client-side from each card's `data-tag`.

### Post contract (enforced by `validatePost`)

Metadata is read from `<head>` first, with `<h1>` / `.article-tag` / `.article-lede` as fallbacks:

```html
<title>Title | Candor</title>
<meta name="description" content="Card excerpt + og:description (aim for ≤160 chars)" />
<link rel="canonical" href="https://candorcertified.com/blog/{slug}" />   <!-- must match the filename -->
<meta name="article:section" content="Tag" />
<meta property="og:type" content="article" />  og:title · og:description · og:url (= canonical) · og:image · og:site_name=Candor · article:published_time
<meta property="twitter:card" content="summary_large_image" />  twitter:title · twitter:description · twitter:image
<!-- JSON-LD: Article { "datePublished": "YYYY-MM-DD", "dateModified": "YYYY-MM-DD" } + BreadcrumbList; FAQPage only with a matching visible FAQ -->
<!-- consent-default block (candor-consent-default:start) + Google Tag Manager GTM-NKSHZN82 + gtag G-DE7YHS643Z -->
```

```html
<header class="article-header">
  <span class="article-tag">Tag</span>
  <h1>Exactly one h1</h1>
  <p class="article-lede">Framing paragraph shown under the title</p>
  <div class="article-meta">
    <span>Artem Furman</span><span class="sep">·</span><span>Month YYYY</span><span class="sep">·</span><span>N min read</span>
  </div>
</header>
<hr class="article-divider" />
<article class="article-body">…</article>
```

- `og:image` / `twitter:image` = the first article image as an absolute `https://candorcertified.com` URL, else `https://candorcertified.com/images/heroes/webshare.jpg`.
- Every `<img>` needs `alt`, real `width`/`height` (`identify -format "%w %h" file`), and `loading="lazy" decoding="async"` on all but the first image. Images live in `blog/images/` as compressed `.webp`/`.jpg`; the `<figcaption>` states the source/licence.
- The consent banner (`candor-consent:start`) and footer legal links are injected by `scripts/sync-shared.js`; `publish.js` runs it for you.
- HTML comments are ignored by the validator, so the template's commented examples are safe.
- **Key-point highlights:** wrap the 4–6 most important phrases of each post in `<mark>…</mark>` (plain `<p>`/`<li>` body text only, never headings, links, callouts or the CTA). `sync-shared.js` injects the `candor-highlight` block into every page whose JSON-LD has `"@type": "Article"`; it draws a hand-drawn chisel-marker stroke (SVG, sage `rgba(90,166,114,.40)`, uneven edges, drag streaks, slanted tips) behind each line of each mark, line by line in reading order. The draw is **scrubbed by scroll** (starts when the mark's top crosses 88% of the screen height, complete by 52%) and **posterised to 12 fps** Vox-style: the visible state only updates every 83 ms, and while mid-draw the stroke boils between three hand-drawn variants. Scrolling back up un-draws it the same way. Reduced motion: drawn statically. Without JS a CSS gradient marker shows instead. Backgrounds and text colours are untouched.

### Still-lake hero (blog/index.html)

The listing opens with "Field notes." / "All things B-Corp" over a painted misty lake (`images/heroes/lake-wide.webp` on landscape screens, `lake-tall.webp` on portrait; slots `lake-wide` / `lake-tall`). The painting is the art; a WebGL canvas adds the life: drifting mist bands, a slow swell and occasional drops on the lake, tap/click ripples (tapping the sky ripples its reflection), a very subtle depth parallax (scroll, plus pointer on desktop), and a second small canvas of mist in front of the title: by default the title sits in a translucent, drifting band of mist (heavier on its lower half) that parts softly around the pointer; the title glyphs are redrawn into that canvas (2D-canvas texture placed at DOM Range positions; the DOM text stays for SEO/screen readers but is visually hidden), so the mist can dissolve them: on load the title forms out of mist, and on scroll it fades gently and slightly unevenly into the mist (one broad, slow noise over a soft global fade, scaled in screen pixels; no fine grain, which read as blotchy), the bottom mist rises over a 170svh pinned track and the scene drifts up; the content after the hero is pulled up 30svh (`.lake + *`) so the post cards rise out of the fog under a soft `.lake-lip` mist gradient. The rising fog's height follows the top edge of the incoming posts (not the scroll alone), so the mountains stay visible while the posts arrive and are veiled once the posts pass the middle of the screen, and a drifting `.lake-front` fog band sits in front of the filter bar and first cards, fading out (scroll-linked) as they settle. The stage is `100lvh` so it reaches under Safari's floating address bar on iPhone. The image is colour-matched to the page background `#ECEAE2` so the hand-off is seamless. The waterline and canoe box (where ripples are suppressed) are hard-coded per image in the script, so re-measure them if the art changes. The hero lives between the `still-lake:start/end` (markup), `still-lake:css:start/end` and `still-lake:js:start/end` markers; `rebuildIndex()` never touches it. Fallbacks: no WebGL → the still image with a fade; reduced motion → no ambient motion and no canvas title, the DOM text simply fades. The `<main id="main-content">` landmark (added by `sync-shared.js`) starts just before the hero, so the skip link lands on it. While you read, the title mist is capped at 8% over the letters themselves (so the subheading keeps ≥4.5:1); arrival and the scroll-away dissolve still mist them fully.

### Card logic in blog/index.html

- **Newest post** (by `datePublished`) → featured dark card (multi-column layout)
- **All other posts** → regular cards in reverse chronological order
- The whole `<section class="articles">` block is generated by `rebuildIndex()` — never hand-edit it; run `npm run rebuild`.

### Suggested posts on every post

The `<section class="more-articles">` block at the bottom of every post is generated by `rebuildRelated()` in `scripts/lib/blog.js` (run by `npm run rebuild`, `publish.js` and the watcher): the newest other post, one post with the same tag (picked by a hash of the slug so suggestions vary between posts), then the "All articles" card. A new post therefore shows up under every older post as soon as it publishes. Each post keeps its own grid markup (`cards-grid` or the older `more-grid`). Never hand-edit the block.

### Weekly blog routine

A scheduled routine (Saturdays 8:45 am Pacific, a weekly-recap slot) drafts one post a week following `.claude/skills/blog-publish/SKILL.md`, switching the post type from the previous week (news, tips, fun facts, myth vs fact, case study, explainer…), runs `publish.js --no-git`, and opens a **draft PR** on `claude/blog-<slug>` with the sources and a hero image prompt. Nothing goes live until the user reviews and merges.

### Sitemap

`rebuildSitemap()` regenerates the blog `<url>` blocks between the `<!-- Individual Articles -->` and `<!-- Tools -->` markers in `sitemap.xml` (one per post, `lastmod` = `dateModified`, changefreq monthly, priority 0.8). Everything outside the markers is left untouched — keep both comments in place.

## Styling conventions

All styles live in `<style>` blocks inside each HTML file. Never introduce an external CSS framework, utility library, or separate stylesheet.

### Design tokens

```css
--bg: #ECEAE2;          /* page background (warm off-white) */
--ink: #0D1610;         /* primary text, dark backgrounds */
--ink2: #141f17;        /* darker ink variant */
--green: #2D6B42;       /* primary brand green */
--forest: #2D6B42;      /* alias for --green */
--field: #3D8A57;       /* mid-tone green */
--sage: #5AA672;        /* lighter green */
--oat: #ECEAE2;         /* alias for --bg */
--paper: #F5F3EE;       /* cream/card background */
--body: #4A5548;        /* body text dark gray */
--stone: #C8C3B5;       /* mid-tone neutral — rules/borders only, never text on light backgrounds */
--muted: #64625A;       /* secondary text (meta lines, captions): 5.1:1 on --bg, 5.5:1 on --paper, 4.7:1 on --light */
--light: #E4E1D6;       /* light neutral */
--u: "Urbanist", sans-serif;
--mono: "Space Mono", monospace;
--ease: cubic-bezier(.16,1,.3,1);   /* elastic out — primary animation easing */
--ease2: cubic-bezier(.4,0,.2,1);   /* smooth decelerate */
--px: clamp(20px, 5vw, 80px);       /* responsive horizontal padding */
```

Text contrast (WCAG 2.2 AA needs 4.5:1 for body text): `--sage` and `--stone` fail as text on `--bg`/`--paper` (2.4–2.7:1 and 1.5–1.6:1), so small secondary text uses `--muted`; `--field` passes only for large text, and on the dark assessment page small labels use `--sage` (6.3:1 on `--ink`). The full token contrast table, review checklist and evidence-graded UX principles are in `.claude/skills/ux-review/SKILL.md`; use it for any design critique or visual change.

## Deployment

Netlify publishes the repo root directly. Key `netlify.toml` rules:

| Rule | Detail |
|---|---|
| HTML caching | `Cache-Control: public, max-age=0, must-revalidate` (never cached) |
| JS/CSS | `immutable`, `max-age=31536000` |
| Images | `max-age=2592000` (30 days) |
| Fonts | Immutable, long-term |
| Blog rewrite | `/blog/:slug` → `/blog/:slug.html` (status 200) |

Do **not** add `force = true` trailing-slash redirects for directory pages: Netlify matches `/terms` and `/terms/` with the same rule, so a forced `/terms → /terms/` rule loops. Netlify's own pretty-URL handling already adds the slash.

**Security headers on all routes:**
- `X-Frame-Options: DENY`
- `Content-Security-Policy` — allows `'unsafe-inline'` (needed for inline styles/scripts), Calendly, Google Fonts, Google Tag Manager / GA4 (`googletagmanager.com`, `*.google-analytics.com`, `*.analytics.google.com`), the Apps Script endpoint; also sets `base-uri`, `object-src 'none'`, `frame-ancestors 'none'`, `form-action`, `upgrade-insecure-requests`. Any new third-party script/host must be added here or it is silently blocked.
- `Strict-Transport-Security` with preload (1 year)
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy`: blocks camera, microphone, geolocation

When adding a new top-level page or route, check whether a redirect/rewrite rule is needed in `netlify.toml`.

| Path | Role |
|---|---|
| `privacy-policy/index.html` | PIPEDA / BC PIPA privacy policy. Section 7 (`#cookies`) must describe the real cookie behaviour below. |
| `terms/index.html` | Terms of Service, including fees, taxes, cancellation and refund rules. **The refund terms (full refund before kickoff, pro-rata after, 14-day notice on larger tiers, 10-business-day refunds, 50 % deposit) were drafted as sensible defaults — confirm or edit them before relying on them.** |

Both pages share the privacy-policy shell (nav, `article-header`, `article-body`, `policy-table`, footer). When one changes structurally, mirror it in the other.

### Cookie consent (Google Consent Mode v2)

- Every page starts `<head>` with the `candor-consent-default` block: `analytics_storage` and all ad signals default to **denied**; a stored `localStorage['candor-consent'] === 'granted'` upgrades analytics to granted before GTM/gtag load.
- Every page ends `<body>` with the `candor-consent` banner (Accept analytics / Decline, Escape = decline). A `navigator.globalPrivacyControl` signal is treated as decline and suppresses the banner.
- Footer legal links on every page: Privacy Policy · Terms · Cookie settings (`data-consent-open` reopens the banner).
- `loaderSeen` is **sessionStorage**, not a cookie. Keep the privacy policy's storage table in sync if any of this changes.
- GA4 property `G-DE7YHS643Z` is loaded twice today: directly via gtag.js and via GTM container `GTM-NKSHZN82`. If the GTM container also fires a GA4 configuration tag, page views are double-counted — check the container and remove one.

### `scripts/sync-shared.js`

Owns the snippets above, the site footer (`candor-footer:start/end`: brand line, two CTAs, Navigate / Resources columns flush right, legal row with Privacy · Terms · Cookie settings · LinkedIn, disclaimer, faint oversized wordmark) and the footer's contact popup (a `<dialog>` with a Netlify Forms form named `contact`, opened by any `[data-contact-open]` link, posting with fetch; on failure it shows the email address; requires Netlify form detection + an email notification set up in the Netlify UI), plus the shared accessibility block (`:focus-visible` outline, `.sr-only`, skip link → `#main-content`) and the shared nav sizing: the "Book a free call" button never wraps; below 1100px the nav links tighten and below 940px they hide, with the button pinned right. It also wraps each page's content in a `<main id="main-content">` landmark (skip-link target → footer) when the page has none. The consent banner never takes focus on its own (Accept and Decline stay equal); while it is open `html.cc-open` is set, which adds bottom scroll-padding so keyboard focus scrolls clear of it and hides the homepage's floating nav pill. The a11y block keeps the native I-beam in text fields under the custom dot cursor and rings the dot so it shows on dark sections. Run `node scripts/sync-shared.js` after creating any new page, and `node scripts/sync-shared.js --check` before committing. Never hand-edit content between `candor-*:start/end` markers — edit the script and re-run it.

### Claims policy

- No testimonials or reviews exist on the site; do not add any that are not from real, named clients with permission.
- Every statistic needs a named, dated source (the `#stats` section pattern). Retail/buyer requirement claims in the industry cards are deliberately phrased as "increasingly ask for", never "require".
- The assessment's results are **modelled estimates** and are labelled as such on the results screen; keep that disclaimer if the layout changes. (The old CO₂, workforce and "73 %" figures were removed; `co2`/`workers` stay as blank sheet columns.)
- Prices are CAD, exclude GST/PST, and the "$12,000+" scope note under the pricing tiers must stay in sync with the Terms.

### Images

All JPEGs are recompressed (quality ~76, max 1920 px wide; industry cards 1600 px; portrait and OG image 1200 px). Keep new images under ~300 KB, give every `<img>` `alt`, `width`, `height`, and `loading="lazy"` unless it is above the fold. Blog photos of third-party companies need a stated source/licence in the figcaption.

## Image system

`images/README.md` is the source of truth: every image has a named slot in `scripts/lib/image-slots.js`. Workflow: save a file as `images/_inbox/<slot>.png` → `npm run images` (sharp resizes/compresses into the slot's path; the HTML already references it). Blog heroes: `images/_inbox/blog-<slug>.png` → `blog/images/<slug>.webp` → `npm run rebuild` or `publish` injects the figure, share tags and featured-card background. Share cards: `npm run og -- --all | --site` renders `scripts/templates/og.html` with Playwright. Slots `hero-art`, `lost-trail` and `og-bg` are decorative and fall back silently when the file is missing (`onerror="this.remove()"`). `images/textures/grain.png` is a 4 KB tile laid over every page by `sync-shared.js` (soft-light, desktop only). `404.html` is served by Netlify automatically for unknown routes and is `noindex`. Never generate a face to represent Artem; never put text, logos or certification marks inside images.
